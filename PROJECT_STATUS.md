## 2. Цель и подтверждённый объём

SQL Academy обучает самостоятельному решению аналитических задач на SQL с нуля до уверенного Junior Data Analyst. PostgreSQL — отдельный дополнительный маршрут, без смешения с администрированием в основном курсе.

- Основной маршрут: 17 модулей, 112 уроков.
- PostgreSQL: 8 модулей, 61 урок.
- Всего: 25 модулей, 173 урока.
- Практика: 130 обычных заданий и 350 случайных вариантов по 14 темам.
- Контроль знаний: 100 вопросов.
- Учебная БД: 14 seed tables.
- Практические проекты: E-commerce, Delivery и Product Analytics; по три SQL-задачи в каждом.

Стабильные ID уроков и заданий сохраняются. Если изменение ID станет неизбежным, обязательна безопасная миграция существующего прогресса.

## 4. Завершённая функциональная база

- Раздельные каталоги и прогресс двух учебных маршрутов.
- Hash-навигация, прямые ссылки, reload, Back/Forward.
- SQL Playground на PGlite и редактор CodeMirror.
- Практика, контрольные, справочник и глоссарий.
- Три проекта с SQL-проверкой и итоговой аналитической частью.
- Светлая и тёмная темы, мобильная навигация.
- Автосохранение прогресса и черновиков в localStorage.
- JSON backup с проверкой структуры, подтверждением и rollback при ошибке.
- Миграция legacy lesson IDs.
- CI: проверка синтаксиса JS, curriculum/PGlite smoke, Pages deploy и Playwright browser-smoke опубликованного сайта.

Известные продуктовые ограничения: PGlite работает в памяти браузера; прогресс и черновики привязаны к браузеру/origin; облачной синхронизации нет. Перенос между устройствами выполняется через backup.

## 5. Последняя завершённая задача и одна текущая задача

### Последняя завершённая задача — модуль `security` дополнительного маршрута PostgreSQL

Все семь уроков модуля проверены. Примеры и задания разделены на то, что реально можно проверить в PGlite, и операции, для которых нужна настоящая серверная среда.

- Уточнено, почему конкатенация пользовательского ввода создаёт SQL-инъекцию и почему ручная замена кавычек не является защитой.
- Пример параметризации теперь показывает полный цикл PREPARE / EXECUTE / DEALLOCATE; отдельно объяснено, что в приложении значения передаются через API драйвера.
- RLS-политика теперь безопасно закрывает доступ, если контекст магазина не установлен. Объяснено, что tenant-контекст должен задаваться доверенным серверным кодом.
- Добавлены правила для SECURITY DEFINER: минимальные привилегии, безопасный search_path и доверенные схемы.
- Динамический SQL показан полноценным DO-блоком с белым списком идентификаторов, format('%I') и USING для значений.
- Уточнено, что pg_dump/pg_restore — внешние инструменты, а успешный backup нужно подтверждать тестовым восстановлением.
- Добавлено `e129`: параметризованная SQL-функция с позиционным параметром $1.
- Добавлено `e130`: динамический SQL с проверкой белого списка, безопасным идентификатором и отдельной передачей значения.
- Не добавлялись фиктивные PGlite-тесты для GRANT/REVOKE, реальных ролей, RLS и backup/restore: для них нужны отдельные серверные роли, подключения и инструменты.
- Всего теперь 130 практических заданий; обновлены README, семь cache-busting imports и build `20261110-138`. Существующие IDs сохранены.

**Фаза 3 — практика, контроль и проекты.**

Работать по существующим материалам, не добавляя задачи ради количества:
- проверить соответствие каждого задания уроку и месту в последовательности курса;

- проверить валидатор эквивалентных корректных SELECT / WITH SELECT и изменяющих заданий;
- проверить 350 случайных заданий по 14 темам: разнообразие, сложность, корректность решений и отсутствие повторов;
