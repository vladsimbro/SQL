## Что представляет собой проект

SQL Academy — интерактивная платформа для самостоятельного изучения SQL с нуля до уровня Junior Data Analyst. В ней есть основной аналитический курс и отдельный дополнительный маршрут по PostgreSQL.

На текущий момент в проекте:
- основной маршрут — 17 модулей и 112 уроков;
- дополнительный маршрут PostgreSQL — 8 модулей и 61 урок;
- 113 практических заданий и 350 случайных вариантов;
- 100 вопросов для проверки знаний;
- учебная база данных и три практических аналитических проекта.

## Что уже работает

- Отдельные учебные маршруты и сохранение прогресса по ним.
- Интерактивная среда, в которой можно писать и выполнять SQL-запросы.

## Последнее сделанное

### Последняя задача: модуль PostgreSQL — изменение и удаление данных (DML)

В этой части курса улучшено объяснение безопасного изменения данных и добавлены практические задачи на два важных механизма PostgreSQL.

Что изменилось:
- Уточнено, почему UPDATE и DELETE без точного WHERE могут затронуть все строки таблицы.
- Исправлены подсказки, которые повторялись или относились к другой команде.
- Объяснено важное ограничение UPSERT: для обновления при конфликте нужен подходящий уникальный ключ или индекс.
- Добавлена задача, в которой нужно изменить запись и сразу получить её новое состояние через RETURNING.
- Добавлена задача MERGE: обновить найденную запись, сохранить не затронутую и добавить новую.
- Автоматическая проверка теперь сравнивает точный результат RETURNING и итоговое содержимое после MERGE.

Теперь в платформе **113 практических заданий**, включая 18 заданий с изменением данных. Прежние идентификаторы уроков и заданий сохранены.

Проверка: GitHub Actions успешно выполнил проверку JavaScript и полную проверку учебной программы и решений заданий. Изменения объединены в main. Пост-merge публикация build 133 пока отдельно не подтверждена.

### Предыдущая задача: модуль PostgreSQL — добавление данных (INSERT)

В этой части курса улучшено объяснение того, как PostgreSQL добавляет записи и какие значения база подставляет самостоятельно.

Что изменилось:
- Разобрано отличие между пропущенным столбцом, `DEFAULT` и явным `NULL`.
- Объяснено, как получить ID только что созданной записи через `RETURNING`, не рискуя получить ID чужой параллельной вставки.
- Исправлено название одного задания: оно теперь действительно про добавление товара, а не категории.
- Исправлены подсказки, которые повторялись или относились к другой теме.
- Добавлены две новые практические задачи: на значения по умолчанию и автоматический ID, а также на добавление нескольких строк одной командой.
- Уточнено, что импорт через `\copy` относится к клиенту psql и не запускается в браузерной SQL-песочнице.

В итоге в платформе стало **111 практических заданий вместо 109**. Прежние идентификаторы уроков и заданий сохранены.

Проверка: автоматическая проверка кода и учебной программы прошла успешно в GitHub Actions. Изменения объединены в основную ветку. Пост-merge публикация и браузерная проверка build 132 пока отдельно не подтверждены.

### Ранее: модуль PostgreSQL — изменение структуры таблиц (DDL)

В этой части курса улучшены объяснения и примеры, чтобы ученик понимал не только синтаксис, но и последствия изменения структуры базы данных.

Что добавлено и исправлено:
- Объяснено, когда добавление столбца со значением по умолчанию проходит быстро, а когда может затронуть всю таблицу и вызвать блокировки.
- Уточнена работа автоматически генерируемых идентификаторов.
- Исправлен пример связи двух таблиц по нескольким полям.
- Улучшен пример безопасного добавления ограничений к таблице, в которой уже есть данные.
- Добавлено шесть новых практических заданий по реальным сценариям изменения таблиц и ограничений.
- Каждое из восьми занятий модуля теперь связано с подходящим практическим заданием.

## Как читать этот журнал

- «Сделано» означает, что изменение внесено и его результат подтверждён.
- «В работе» означает, что задача ещё не закрыта.
- «Дальше» показывает ближайшую конкретную задачу, а не весь список возможных улучшений.
- Идеи, не необходимые для релиза, не добавляются в обязательный план.

Журнал обновляется после каждой завершённой логической задачи. Технические подробности и точные результаты проверок не дублируются здесь — для них предназначен PROJECT_STATUS.md.
